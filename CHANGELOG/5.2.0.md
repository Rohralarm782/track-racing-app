# 5.2.0

- **Datum:** 26.09.2026
- **Typ:** KLEIN (neue Funktion, alles Bestehende bleibt)

## Anlass

Die automatische MEV-Erkennung lag an diesem Wochenende mehrfach daneben:
ZG/GG fehlte bei U17w/U19m/U19w, Inga (LV „BER") wurde bei U17w als MEV
geführt, bei U19w verschwand Dorothea ganz. Trackside braucht es einen Weg,
die Fahrerliste eines Kommuniqués direkt zu korrigieren, ohne auf die nächste
Neuauswertung zu hoffen.

## Änderung

Im Zeitplan neben „ändern" ein neuer Link **„✏️ Fahrer bearbeiten"** (nur für
Admins, nur wenn ein Kommuniqué verknüpft ist). Er öffnet eine Liste mit Name,
Lauf und Position (ZG/GG/B/M) je Fahrer, vorbefüllt mit der aktuellen
Erkennung.

- **Speichern** schreibt die Liste in `mevRiders` und setzt das Dokument auf
  `mevManual`. Ab dann überspringen automatischer Poll, Roster-Nachlauf und
  „Neu analysieren" dieses Dokument — Muster wie `classificationManual`.
- Die MEV-Zeile ist dann **lila mit Kennzeichen „MANUELL"** statt gelb.
- **„↺ Zurück auf automatisch"** (nur bei manuellen Dokumenten) hebt die
  Sperre auf, leert die Liste und setzt `mevVersion` auf 0 — der nächste Poll
  (≤ 90 s) wertet das Dokument garantiert neu aus.
- Der Sortierfix aus 5.1.3 gilt auch für von Hand eingetragene Fahrer; die
  geschätzte Lauf-Startzeit (~hh:mm) wird wie bisher aus Lauf-Nummer und
  Laufzahl berechnet.

Die manuelle Liste gilt für das **Dokument**, nicht für den Zeitplan-Eintrag:
hängt dasselbe Dokument an zwei Einträgen (geteilte Ansetzung), gilt sie an
beiden.

## Breaking Changes

**Schema-Änderung → `npx prisma db push` erforderlich** (läuft auf Render im
Startbefehl automatisch). Rein additiv: ein neues Feld mit Vorgabewert
`false`, alle bestehenden Dokumente bleiben automatisch. Keine Neuauswertung,
`MEV_ANALYSIS_VERSION` bleibt 9.

## Rollback

Frontend zuerst (sonst ruft die UI nicht mehr vorhandene Routen), dann
Backend, dann `schema.prisma` auf 5.1.3 und `npx prisma db push` — Prisma
entfernt dabei die Spalte `mevManual` (ggf. mit `--accept-data-loss`); die von
Hand eingetragenen Fahrer bleiben in `mevRiders` stehen, bis der nächste
reguläre Analyseanlass sie überschreibt.

## Deploy-Reihenfolge

`schema.prisma` → Backend → Frontend. Werden Backend und Frontend nicht im
selben Zug deployt, zeigt das alte Frontend einfach keinen neuen Link —
unkritisch.
