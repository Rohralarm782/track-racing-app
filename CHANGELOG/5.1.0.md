# 5.1.0

- **Datum:** 25.09.2026
- **Typ:** KLEIN (neue Funktion + Fehlerbehebung, nichts Bestehendes entfernt)

## Anlass

Zwei Beobachtungen aus einem Zeitplan-Screenshot derselben Veranstaltung
(BDR-Sichtung Bahn, 25.09.2026):

1. Bei U17m stand als einzige der vier Startaufstellungen eine Startposition
   („GG") mit im Zeitplan — bei U17w/U19w/U19m fehlte sie ganz, obwohl
   dieselbe Information (Zielgerade/Gegengerade) in allen vier Dokumenten
   grundsätzlich vorhanden ist.
2. Bei U17m fehlte mindestens ein MEV-Fahrer (Friedrich Bierwerth, HSG Uni
   Greifswald), obwohl sein Verein in einem anderen Dokument derselben
   Veranstaltung eindeutig als MEV ausgewiesen ist (LV-Spalte).

## Ursache

**Zu 1.:** Die vier BDR-Kommuniqués schreiben dieselbe Information
uneinheitlich in die Lauf-Spalte: U17m benutzt „ZG 1"/„GG 1", die anderen drei
nur „Z 1"/„G 1". Der Analyse-Prompt in `analyzeMevForDocument`
(`backend/src/lib/mevDetect.ts`) suchte für `startPos` bisher ausschließlich
nach den Literalen „ZG"/„GG" bzw. nach einem Hinweissatz unter der Tabelle
(„Die erstgenannte Fahrerin startet von der Zielgeraden") — beides fehlte in
den drei Dokumenten mit der Kurzform „Z"/„G", die Position ging deshalb
kommentarlos verloren.

**Zu 2.:** Kommuniqués ohne eigene LV-Spalte (wie das U17m-Dokument) werden
bisher nur über einen Roster erkannt, der ausschließlich aus **anderen
Dokumenten derselben Altersklasse mit LV-Spalte** abgeleitet wird
(`loadMevRoster`). Ein Fahrer, der noch in keinem solchen Dokument der
Altersklasse vorkam, fällt durch — unabhängig davon, wie eindeutig sein Verein
ist. Es gab bisher keine Möglichkeit, das von Hand zu ergänzen.

## Änderung

**ZG/GG-Erkennung erweitert:** `analyzeMevForDocument`-Prompt erkennt jetzt
zusätzlich einzelne Buchstaben-Codes direkt in der Lauf-Spalte selbst
(„Z 5"/„G 5" → „ZG"/„GG", genau wie „ZG 5"/„GG 5") als gleichwertiges Signal,
unabhängig von der Lauf-Nummer-Erkennung. Der bisherige Hinweissatz-Mechanismus
bleibt als Fallback bestehen, falls die Lauf-Spalte gar keinen Buchstaben-Code
enthält.

**Manuelle MEV-Startnummern je Veranstaltung (neu, ergänzend):** neue Karte in
den Veranstaltungs­einstellungen — sechs feste Altersklassen (U15/U17/U19 ×
m/w) als Reiterleiste, je AK eine Liste von Startnummern (optional mit Notiz
nur zur eigenen Orientierung, fließt nicht in den Abgleich ein). Diese Liste
**ergänzt** den automatischen LV-Spalten-Roster nur dort, wo er nichts findet
— eine bereits automatisch bekannte Startnummer wird nie überschrieben.
Matching läuft wie beim bestehenden Roster im Analyse-Prompt selbst (keine
serverseitige Nachbearbeitung).

`MEV_ANALYSIS_VERSION` 8 → 9 (deckt beide Änderungen in einer gemeinsamen
Neuauswertung ab).

## Breaking Changes

**Schema-Änderung:** neues Modell `MevStartNumber` + neue Relation an `Event`.
**`npx prisma db push` erforderlich**, bevor das Backend deployt wird. Reine
Erweiterung (neue Tabelle, neue optionale Relation) — keine bestehende Spalte
wird verändert oder entfernt, keine bestehenden Daten betroffen.

`MEV_ANALYSIS_VERSION` 8 → 9 löst beim nächsten Poll eine **Neuauswertung
aller bereits analysierten Kommuniqués der laufenden Veranstaltungen** aus
(Haiku-Kosten, siehe 5.0.1 zur Größenordnung — hier aber einmalig pro
Dokument, nicht wiederholt).

## Rollback

Reihenfolge rückwärts: Frontend zuerst zurücksetzen (verweist sonst auf eine
Route, die nicht mehr existiert), dann Backend, dann `schema.prisma` +
`npx prisma db push` auf den 5.0.1-Stand. Bereits über die neue Karte
eingetragene Startnummern (Tabelle `MevStartNumber`) bleiben in der Datenbank
liegen, werden nach dem Rollback aber von keinem Code mehr gelesen — beim
erneuten Hochziehen dieser Version stehen sie unverändert wieder zur
Verfügung.

## Deploy-Reihenfolge

`schema.prisma` (+ `npx prisma db push`) → Backend (`index.ts`,
`mev-startnumbers.ts`, `mevDetect.ts`) → Frontend. Zwischen Backend- und
Frontend-Commit ist ein roter Build am UI-seitigen Import von
`MevStartNumbersSettings` erwartbar, falls Backend und Frontend nicht im
selben Zug deployt werden — angekündigt, unkritisch.
